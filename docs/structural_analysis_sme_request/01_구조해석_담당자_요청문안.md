# 구조해석 의뢰 Agent 확장을 위한 자료 및 검토 요청

## 메일 제목

`[검토 요청] 구조해석 의뢰 Agent 확장을 위한 유형·입력조건 정의`

## 전달 문안

안녕하세요.

비전문 사용자도 구조해석을 쉽게 의뢰할 수 있도록 기존 유동해석 의뢰 Agent를 확장하려고 합니다.

이번 확장의 목표는 구조해석 계산 설정을 완전히 자동화하는 것이 아닙니다. 사용자가 목적, 대상 제품, 재질, 하중, 구속, 연결 상태와 결과 판정기준을 빠짐없이 전달하여 구조해석 담당자가 별도 재문의 없이 해석 착수 여부를 판단할 수 있게 하는 것이 목표입니다. 메시, 솔버, 접촉 알고리즘, 수렴 기준처럼 해석자가 판단해야 하는 항목은 사용자 필수 입력에서 제외하려고 합니다.

초기에는 자주 수행하고 입력을 표준화하기 쉬운 대표 구조해석 2~3종만 선정하여 구현할 예정입니다. 담당자께 데이터 구조나 프로그램 설계를 요청드리는 방식은 지양하고, 실제 의뢰 사례와 업무 규칙을 바탕으로 개발자가 입력 Master를 작성한 뒤 담당자께서 누락과 오류를 검수하는 방식으로 진행하고자 합니다.

다음 자료와 검토를 요청드립니다.

1. 후보 구조해석 유형과 업무상 우선순위
2. 후보 유형별 익명화된 실제 의뢰서·보고서·입력자료 3건 이상
3. 의뢰자가 반드시 제공해야 하는 정보와 구조 담당자가 판단해야 하는 정보의 구분
4. 재질, 하중, 구속, 접촉·체결, 해석 Case와 결과 판정 규칙
5. 정보가 없거나 애매할 때 실제로 확인하는 후속 질문
6. 개발자가 작성한 Field Rule Master와 샘플 의뢰서의 최종 검수

첨부한 `구조해석_담당자_회신양식.xlsx`에서는 우선 `01_해석유형_우선순위`와 `02_완료사례_목록` 시트만 작성해 주시면 됩니다. 나머지 Master 시트는 1차 워크숍에서 실제 사례 한 건을 함께 검토한 후 개발자가 초안을 작성하겠습니다.

실제 자료 제공이 어려운 경우에는 프로젝트명, 도면번호, 담당자명 등을 익명화하거나 동일한 구조를 가진 예시 데이터로 대체해 주셔도 됩니다.

## 제안 일정

- 자료 사전 회신: `[회신 희망일 입력]`
- 1차 워크숍: 후보 유형 평가, MVP 2~3종 선정, 대표 사례 한 건 분해
- 개발자 초안 작성: Field Rule, 핵심 객체, Case 조합, 사용자 질문
- 2차 워크숍: 필수·조건부·담당자 판단 항목 및 예외 확정
- 최종 검수: 유형별 사례 3건 재현 및 착수 가능 여부 승인
