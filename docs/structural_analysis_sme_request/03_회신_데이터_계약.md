# 구조해석 담당자 회신 데이터 계약

이 문서는 `구조해석_담당자_회신양식.xlsx`의 시트와 열 의미를 정의한다. Excel의 작성 예시는 설명용이며 승인값이 아니다.

## 공통 상태값

- 검수 상태: `작성 중`, `검토 필요`, `담당자 검수 완료`, `최종 승인`
- 필수 수준: `필수`, `조건부 필수`, `선택`, `담당자 판단`
- 입력 주체: `의뢰자`, `구조 담당자`, `시스템 계산`
- 예/아니오형 값: `예`, `아니오`, `해당 없음`, `검토 필요`
- 오류 수준: `제출 차단`, `경고`, `안내`, `해당 없음`

## 01_해석유형_우선순위

후보 해석유형을 빈도, 표준화 가능성 및 입력 확보 난이도로 평가하여 MVP 2~3종을 선정한다.

| 열 | 작성 규칙 |
|---|---|
| 행 구분 | `작성 예시` 또는 `실제 입력` |
| 사용자 표시명 | 비전문 사용자 화면에 표시할 명칭 |
| 주요 질문 | 해석으로 답하려는 제품 의사결정 |
| 적용 제품/부품 | 제품군, 어셈블리 또는 부품 범위 |
| 대표 결과 | 응력, 변위, 안전율, 고유진동수, 수명 등 |
| 적용하지 않는 경우 | 다른 해석유형을 선택해야 하는 조건 |
| 수행 빈도 | `높음`, `중간`, `낮음` |
| 표준화 가능성 | `높음`, `중간`, `낮음` |
| 입력 확보 난이도 | `쉬움`, `보통`, `어려움` |
| MVP 추천 여부 | `필수`, `후보`, `향후` |
| 검수 상태 | 공통 상태값 사용 |
| 담당자 의견 | 보완 설명과 결정 근거 |

## 02_완료사례_목록

후보 유형별 최소 세 사례를 기록한다. 민감정보는 익명화한다.

핵심 열은 `사례 구분`, `최초 사용자 요청`, `제품·CAD·도면 정보`, `재질 정보`, `하중 정보`, `구속 정보`, `접촉·체결 정보`, `담당자 추가 질문`, `최종 Case`, `요청 결과`, `판정 기준`, `최종 의뢰서·보고서 위치`다.

## 03_Field_Rule_Master

사용자 입력 화면, Agent 질문, 필수 여부와 검증 규칙의 기준이 된다. `규칙 ID`는 개발자가 부여하며 구조 담당자가 새 영문 키를 설계하지 않는다.

| 열 | 작성 규칙 |
|---|---|
| 입력 그룹 | 제품/형상, 재질, 연결, 구속, 하중, 환경, 결과 요청 등 |
| 사용자 표시명 | 화면과 질문에 사용할 한글 명칭 |
| 정의 | 비전문 사용자가 이해할 수 있는 설명 |
| 적용 해석유형 | 복수인 경우 쉼표로 구분 |
| 필수 수준 | 공통 상태값 사용 |
| 활성 조건 | 다른 선택값에 따른 노출 조건. 항상 활성은 `항상` |
| 입력 주체 | 의뢰자/구조 담당자/시스템 계산 |
| 입력 방식 | 숫자, 텍스트, 단일 선택, 다중 선택, 반복 행, 파일·이미지 표시 등 |
| 단위·좌표계 | 허용 단위와 방향 기준 |
| 선택지·범위 | 선택값, 최소·최대값, 직접 입력 허용 여부 |
| 반복 가능 여부 | 예/아니오 및 필요한 경우 최대 개수 |
| 연결 대상 | 제품, 부품, 면, 하중 세트, Case 등 |
| 모름/해당 없음 | 허용값과 후속 처리 |
| 차단 검증 | 누락 또는 오류 시 제출 차단 조건 |
| 사용자 질문 | Agent가 실제로 사용할 자연어 질문 |
| 정상 예시 | 올바른 사용자 입력 |
| 오류 예시 | 흔한 오류와 수정 안내 |

## 04_핵심객체_규칙

제품/형상, 재질 할당, 연결/접촉, 구속조건, 하중조건, 환경조건, 결과 요청을 반복 가능한 업무 객체로 정의한다. 객체별 최소·최대 개수, 복제 가능 여부, 구성 필드, 연결 대상, 금지 조합과 모름 처리를 기록한다.

## 05_Case_조합규칙

해석유형별 Case 축과 생성 규칙을 정의한다. 형상, 재질 구성, 하중 세트, 구속 세트, 연결 상태와 환경조건 중 실제 Case를 구분하는 축만 지정한다. 동시 하중 여부, 자동 기본 Case, 금지 조합, 중복 판정, 기준 Case, Case 명명 주체 및 조합계수·안전계수 입력 주체를 반드시 확정한다.

## 06_용어_안내_예외

전문용어와 쉬운 설명, 동의어, 필드가 필요한 이유, 기본 질문과 대체 질문, Agent 추정 허용 여부, 사용자 확인 필요 여부, 모름 처리, 오류 수준 및 잘못된 유형 선택 시 추천 유형을 기록한다.

## 07_검수_승인

MVP 해석유형별로 활성 그룹, 필수 규칙, 객체 연결, 모름 처리, 세 사례 재현 및 무재문의 착수 가능 여부를 검수한다. 모든 항목이 `예`이고 구조 담당자와 최종 승인자가 기록되어야 `최종 승인`으로 변경할 수 있다.

## 08_변경이력

Master 버전, 변경일, 작성자, 변경 이유, 영향 시트·해석유형, 기존 의뢰서 호환 여부와 승인 상태를 기록한다.

## 09_워크숍_기록

회차, 일시, 참석자, 목표, 확정 결정, 미결 사항, 담당자와 완료 예정일을 기록한다. 워크숍에서 확정되지 않은 내용을 구두 합의로 간주하지 않는다.
