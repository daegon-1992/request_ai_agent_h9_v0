# 구조해석 정보수집·워크숍·검수 가이드

## 1. 역할 구분

| 역할 | 책임 |
|---|---|
| 구조해석 담당자 | 실제 업무 사례 제공, 해석유형과 업무 규칙 설명, Master 검수·승인 |
| 개발자 | 사례를 정규화하여 Field Rule·객체·Case 규칙 초안 작성, Agent 질문과 검증 규칙 변환 |
| 서비스 기획/운영자 | MVP 범위, 일정, 보안, 변경관리와 최종 운영 승인 |

구조 담당자에게 영문 키, 데이터베이스, JSON 또는 UI 구조를 설계하도록 요청하지 않는다. 개발자가 초안을 만든 뒤 구조 담당자는 업무상 정확성만 판단한다.

## 2. 자료 회수 단계

담당자가 처음부터 모든 Master를 작성하게 하지 않는다. 다음 순서로 자료를 받는다.

1. 기존 구조해석 의뢰 양식과 가이드
2. 후보 해석유형 목록
3. 후보 유형별 실제 완료 사례 3건 이상
4. 최초 요청과 최종 확정 조건의 차이
5. 담당자가 실제로 추가 질문한 내용
6. 최종 결과 항목과 판정 기준

사례는 다음 세 종류를 포함해야 한다.

- 정상적인 단일 하중·단일 형상 사례
- 여러 하중, 형상 또는 조건을 비교한 다중 Case 사례
- 입력 누락, 조건부 필드 또는 담당자 재문의가 있었던 사례

## 3. 1차 워크숍

권장 시간은 90분이다.

### 의제

1. 서비스 목표와 “담당자 착수 가능”의 의미 확인
2. 후보 해석유형을 빈도, 표준화 가능성, 입력 확보 난이도로 평가
3. MVP 2~3종 확정
4. 대표 사례 한 건을 최초 요청부터 최종 의뢰서까지 순서대로 분해
5. 의뢰자 입력, 담당자 판단, 시스템 계산 항목 구분
6. 미결정 사항과 추가 자료 담당자 지정

### 반드시 확인할 질문

- 사용자가 실제로 해결하려는 의사결정은 무엇인가?
- 이 해석유형을 선택하면 안 되는 상황은 무엇인가?
- 어떤 정보가 없으면 착수할 수 없는가?
- 값 대신 사진, 도면 또는 CAD 표시가 필요한 항목은 무엇인가?
- 사용자가 모를 수 있는 값은 누가 어떻게 보완하는가?
- 여러 하중이 동시에 적용되는가, 별도 Case로 나뉘는가?
- 어떤 결과와 기준이 있어야 의뢰 목적을 달성했다고 판단하는가?

## 4. 개발자 초안 작성

개발자는 실제 사례를 다음 Master로 변환한다.

- 해석유형 우선순위
- Field Rule Master
- 제품/형상, 재질, 연결, 구속, 하중, 환경, 결과 요청 객체 규칙
- Case 조합 규칙
- 용어, 사용자 안내와 예외 처리

필드마다 필수 수준, 활성 조건, 입력 주체, 입력 방식, 단위, 반복성, 연결 대상, 모름 처리, 제출 차단 여부와 자연어 질문을 작성한다. 불확실한 내용은 임의로 확정하지 않고 `검토 필요`로 표시한다.

## 5. 2차 워크숍

권장 시간은 90분이다.

### 의제

1. Field Rule의 필수·조건부·선택·담당자 판단 구분 검토
2. 하중·구속·재질·연결 객체의 반복 및 연결 규칙 검토
3. Case 축, 중복, 금지 조합과 기준 Case 검토
4. `모름`, `해당 없음`, `담당자 협의 필요` 처리 확정
5. 제출 차단 오류와 경고 구분
6. 비전문 사용자용 질문과 도움말 표현 검토
7. 남은 미결정 사항과 승인 조건 확정

## 6. 최종 검수

MVP 해석유형마다 최소 세 사례를 Master만 사용하여 다시 구성한다. 다음 질문에 모두 `예`라고 답할 수 있어야 승인한다.

- 활성 입력 그룹과 필수·조건부 필드가 결정되었는가?
- 재질·하중·구속·연결·결과 요청의 적용 대상이 명확한가?
- Case 생성과 중복·금지 조합 규칙이 명확한가?
- 사용자가 값을 모를 때의 후속 질문 또는 담당자 이관 방식이 있는가?
- 불완전 사례에 대해 제출 차단과 경고가 구분되는가?
- 세 사례의 최종 의뢰 내용이 구조 담당자의 예상과 일치하는가?
- 구조 담당자가 추가 전화나 메일 없이 착수 여부를 판단할 수 있는가?

최종 승인 전에는 해당 Master를 h7_v0 구현 기준으로 사용하지 않는다.

## 7. 범위 밖 항목

다음 항목은 구조 담당자가 별도로 “사용자 입력이 반드시 필요하다”고 승인하지 않는 한 의뢰자의 필수 필드로 만들지 않는다.

- 솔버 및 해석 코드 선택
- 요소 종류와 메시 크기
- 접촉 알고리즘의 수치 설정
- 비선형 증분과 수렴 설정
- 후처리 상세 옵션
- 담당자가 표준 절차로 결정할 수 있는 계산 제어값

열-구조 연성, 비선형 접촉, 충격 등 별도 입력체계가 필요한 해석은 MVP로 명시적으로 선정된 경우에만 작성 범위에 포함한다.
