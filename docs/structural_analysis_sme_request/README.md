# 구조해석 담당자 정보요청 패키지

이 폴더는 h7_v0를 구조해석 의뢰까지 확장하기 전에 구조해석 담당자(SME)로부터 업무 규칙을 수집하고 승인받기 위한 전달용 패키지다. 이번 단계에서는 애플리케이션 코드, 공개 API, 상태 스키마를 변경하지 않는다.

## 패키지 구성

| 파일 | 용도 |
|---|---|
| `01_구조해석_담당자_요청문안.md` | 메일·메신저에 바로 붙여 넣는 요청 문안 |
| `02_작성_워크숍_검수_가이드.md` | 자료 회수, 1·2차 워크숍, 승인까지의 진행 지침 |
| `03_회신_데이터_계약.md` | Excel 각 시트의 열 정의와 작성 규칙 |
| `04_h7_v0_현행_유동해석_기준.md` | 동일 기준으로 역정리한 현재 h7_v0 유동해석 동작과 Gap |
| `구조해석_담당자_정보요청서.docx` | 담당자에게 전달하는 정식 요청서 |
| `구조해석_담당자_회신양식.xlsx` | 해석유형, 사례, Field Rule, 객체·Case 규칙 및 승인을 수집하는 양식 |
| `h7_v0_현행_유동해석_기준서.docx` | 구조 담당자가 참고할 수 있는 현행 CFD 기준 예시본 |
| `h7_v0_현행_유동해석_Field_Master.xlsx` | 현행 CFD 유형·필드·객체·Case·검증과 Gap의 코드 기준 정리본 |

Word와 Excel 파일은 다음 명령으로 다시 생성할 수 있다.

```powershell
python tools/build_structural_sme_request_pack.py
```

산출물의 구조와 필수 시트를 검사하려면 다음 명령을 사용한다.

```powershell
python tools/build_structural_sme_request_pack.py --check
```

현행 h7_v0 유동해석 기준 예시본은 다음 명령으로 다시 생성하고 검사할 수 있다.

```powershell
python tools/build_h7_current_cfd_reference.py
python tools/build_h7_current_cfd_reference.py --check
```

## 권장 사용 순서

1. `01_구조해석_담당자_요청문안.md`를 이용해 요청 목적과 범위를 먼저 공유한다.
2. Word 요청서와 Excel 회신양식을 함께 전달한다.
3. 필요하면 `h7_v0_현행_유동해석_기준서.docx`와 `h7_v0_현행_유동해석_Field_Master.xlsx`를 작성 예시로 함께 제공한다.
4. 담당자는 `01_해석유형_우선순위`와 `02_완료사례_목록`부터 작성한다.
5. 1차 워크숍에서 MVP 2~3종과 실제 사례 한 건을 확정한다.
6. 개발자가 나머지 Master 초안을 작성하고 구조 담당자가 검수한다.
7. 해석유형별 사례가 3건 이상 재현된 뒤 `07_검수_승인`에서 최종 승인한다.

## 중요한 운영 원칙

- 회신양식의 `작성 예시` 행은 설명용이며 승인된 구조해석 규칙이 아니다.
- 현행 CFD 기준 예시본의 `코드 기준 정리 완료`는 구현 사실을 뜻하며 유동해석 담당자의 업무 승인을 뜻하지 않는다.
- 구조 담당자는 업무 용어와 판단 규칙을 확정한다. 영문 필드 키, JSON, Python 구조는 개발자가 후속 설계한다.
- 메시, 솔버, 접촉 알고리즘, 수렴 설정 등 해석자 판단 항목은 비전문 의뢰자의 필수 입력으로 만들지 않는다.
- 실제 사례에는 개인정보, 프로젝트명, 도면번호 등 민감정보를 익명화하거나 대체값으로 치환한다.
- 승인 전 Master는 구현 기준으로 사용하지 않는다.

## 현재 h7_v0와의 연결 기준

기존 `사업부 → 제품군 → Platform → 해석유형 → 제품 형상 → 해석조건 → Case 조합 → 검증·출력` 흐름을 유지한다. 기존 사업부·제품군·Platform 분류와 Base/비교 제품 개념을 재사용하고, 구조해석에 필요한 부품·재질·연결·구속·하중·결과 요청을 승인된 Master에 따라 이후 단계에서 추가한다.
