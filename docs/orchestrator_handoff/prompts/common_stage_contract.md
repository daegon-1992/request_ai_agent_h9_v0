# H5-ORCH 공통 단계 실행 계약

자동 Runner 또는 수동 실행자는 `baseline_prompts.md`의 단계 카드를 이 계약, 최신 Roadmap, 선행 인수인계 문서와 실제 결과에 결합해 매 단계의 실행 프롬프트를 생성한다. 자동 Runner는 `current_stage.md`를 생성하고, 수동 실행자는 `manual_stage_execution.md`의 양식을 사용한다. 생성된 프롬프트는 다음 섹션을 모두 포함해야 한다.

## 1. 현재 상황

- 전체 구현에서 현재 단계의 위치
- 최신 Roadmap 버전
- 반드시 읽을 인수인계 문서
- 조사할 코드의 최소 범위

## 2. 작업 목표

이번 단계에서 달성할 결과를 검증 가능한 문장으로 작성한다.

## 3. 작업 범위

구현·조사 항목을 구체적으로 나열하고 후속 단계 범위를 포함하지 않는다.

## 4. 구현 원칙

매 단계에 다음 공통 원칙을 포함한다.

- 기존 폼과 API 유지
- 승인 전 Request State 변경 금지
- 최신 Request 재조회
- Request version 확인
- LLM 권한 제한
- 기존 규칙·계산·검증·출력 엔진 재사용
- 관련 없는 리팩터링 금지
- 사용자 기존 변경 보존

## 5. 작업 절차

1. Roadmap과 선행 인수인계 문서 확인
2. 관련 코드 최소 조사
3. 구현 또는 조사
4. 직접 최소 검증
5. 인수인계 문서 작성
6. Worker 결과 보고 작성

## 6. 수정 허용 범위

최신 인수인계 문서에서 확인된 실제 파일과 이번 단계 직접 테스트, 단계 문서만 허용한다. 최초 계획의 예상 경로보다 실제 구조를 우선한다.

## 7. 수정 금지 범위

관련 없는 기능, 전체 포맷팅, 대규모 리팩터링, 다음 단계 기능, 대용량 데이터·모델·벡터 DB, 비밀값 파일을 금지한다.

## 8. 필수 검증

단계 카드의 검증과 저장소 `AGENTS.md`의 검증 규칙을 함께 적용한다.

## 9. 과도한 검증 금지

필요성이 입증되지 않은 전체 Suite, 전체 E2E, 모든 조합, 광범위 시각 회귀, 실제 LLM 반복 호출을 금지한다.

## 10. 완료 조건

단계 카드의 완료 조건과 인수인계 문서 존재, 필수 검증 결과가 모두 충족되어야 한다. Worker는 스스로 Roadmap을 완료로 확정하지 않는다.

## 11. 중단 조건

다음 상황에서는 범위를 확대하지 않고 중단한다.

- 기존 구조가 인수인계와 크게 다름
- 선행 계약 충돌
- 승인 우회 또는 데이터 손실 위험
- 기존 API 호환성 파괴
- 파괴적 DB 변경 필요
- 사용자 변경과 충돌
- 대규모 리팩터링 필요
- 테스트 환경 부족
- 추가 권한 또는 외부 승인이 필요

## 12. Worker 결과 보고 형식

1. 변경 파일
2. 구현 또는 조사 내용
3. 미수정·미완료 내용
4. 수행한 테스트
5. 테스트 결과
6. 발견된 문제와 위험
7. 다음 단계 영향
8. 생성한 인수인계 문서
9. Git 상태와 Commit 여부

## 13. 인수인계 문서

각 단계 카드에 지정된 경로로 작성하고 다음을 포함한다.

```markdown
# 단계 정보

- 단계 ID:
- 단계명:
- 수행 기준 프로젝트 루트:
- 수행 기준 코드 버전 또는 Commit:
- Roadmap 버전:
- 작업 상태: 완료 후보 / 부분 완료 / 중단 / 검증 불가

# 이번 단계 목표
# 사전 입력 문서
# 실제 수행 내용
# 변경 파일
# 신규 또는 변경된 데이터 구조
# 신규 또는 변경된 API
# 중요 설계 결정
# 기존 기능 재사용 지점
# 수행하지 않은 작업
# 최소 검증
# 실패하거나 실행하지 못한 검증
# 알려진 문제와 제한사항
# 발견된 위험
# 다음 단계에서 반드시 참고할 내용
# 다음 단계 수정이 예상되는 파일
# 후속 개선 후보
# Roadmap 변경 필요 여부
```

## Reviewer 원칙

Worker 종료 후 별도의 Reviewer 실행이 다음을 확인한다.

- 완료 조건과 실제 diff·테스트 근거 비교
- 승인 전 State 불변
- version·동시성·중복 처리
- 기존 API·폼 호환성
- 조건부 필드 유실 위험
- 인수인계 문서 정확성
- 다음 단계 선행조건 충족

Reviewer만 Roadmap 단계 상태와 다음 프롬프트를 확정한다. 수동 실행에서는 Reviewer 결과를 확인한 같은 채팅의 Planner 요청이 이 갱신을 문서에 반영하되, Worker가 자기 결과만으로 완료를 확정해서는 안 된다.
