# Stage 04 — 조건 카드와 해석유형 Template

## 새 채팅에 붙여 넣을 프롬프트

```text
request_ai_agent_h5_v0의 Stage 04만 수행해 주세요.

AGENTS.md, docs/h5_v0_execution_handoff.md와 Stage 03 기록을 먼저 읽으세요. Stage 03이 완료되지 않았으면 구현하지 마세요.

해석조건을 h3 카드 UI로 재구성하세요.
- 사용자 그룹은 운전 조건, 열교환기 사양, 취출 공기 조건, 공간 환경 조건만 제공한다.
- 열교환기 사양은 Fin type, 관 직경, 행 수, FPI를 사용한다.
- 현재 해석유형에 활성인 각 종류의 첫 기본 카드는 삭제할 수 없다.
- 종류별 추가로 만든 두 번째 이후 카드는 삭제할 수 있다.
- 카드 복사, 복제, 복사본 편집은 만들지 않는다.
- 새 카드는 현재 해석유형 Template의 빈 값으로 생성한다.
- 단일 Fan은 간결하게 두고 복수 Fan 설정에서만 Fan 식별·운전/정지·값을 표시한다. 정지 Fan 값은 진행률·검증·Case 원본에서 제외한다. 새 운전 조건에는 Fan 구조만 승계하고 값은 복사하지 않는다.
- 설치 조건은 구현하지 않는다.
- 기류 도달 거리와 PDB는 해석유형 목록, fieldset, Template, Agent 지원, validator, UI에서 완전히 제거한다.
- 일반 조건의 canonical 원본은 Condition Set 카드 하나로 통일한다. 과거 condition_values 등은 새 원본으로 사용하지 않는다.

제품 적용, 조건조합, Case 생성은 다음 단계 범위이므로 구현하지 마세요. 이 단계와 직접 관련된 fieldset/validator/UI 테스트만 수정·실행하고 인수인계를 갱신하세요.
```

## 완료 기준

- 네 조건 그룹만 보이며 설치 조건·PDB·기류 도달 거리 경로가 없다.
- 카드 생성·삭제·복수 Fan 규칙이 State와 UI에서 일치한다.
